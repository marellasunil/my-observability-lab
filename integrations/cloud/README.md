# Optional demo cloud exports

Local telemetry is unchanged. Generate a separate configuration using `python3 scripts/render-cloud.py --grafana --splunk --output /tmp/gateway-cloud.yaml` (omit either flag to disable that destination). No live changes are made. Only demo pipelines fan out; standard application/host pipelines remain local. Sampling is 10%, logs WARN+, metrics allowlisted; these are not hard cost limits. Splunk logs are not exported.

Create a Kubernetes Secret named `otel-cloud-credentials` in observability using a private env file (chmod 600) and `kubectl --context YOUR_CONTEXT -n observability create secret generic otel-cloud-credentials --from-env-file=/private/path/cloud.env`. Required keys for Grafana: GRAFANA_CLOUD_INSTANCE, GRAFANA_CLOUD_TOKEN, GRAFANA_CLOUD_OTLP_ENDPOINT. For Splunk: SPLUNK_ACCESS_TOKEN, SPLUNK_METRICS_ENDPOINT, SPLUNK_TRACES_ENDPOINT. Use exact endpoints from your account, including signal paths for Splunk. Never commit the env file. Add `envFrom: [{secretRef: {name: otel-cloud-credentials}}]` to the gateway container in a separate deployment overlay. Validate the generated config with Collector 0.164.0 and the Secret environment before applying the overlay and ConfigMap. Restart the gateway after config changes. Back up existing config first; restore it and restart to roll back. Do not overwrite a live gateway that already has custom pipelines. The renderer is not an automated deployment or credential manager.
